   125→## Start From A Video You Already Love
   126→
   127→Starting from a reference video is often faster than starting from a blank prompt.
   128→
   129→OpenMontage can start from a **YouTube video, Short, Reel, TikTok, or local clip** and turn it into a grounded production plan:
   130→
   131→1. **Paste a reference video**
   132→2. **The agent analyzes transcript, pacing, scenes, keyframes, and style**
   133→3. **You get 2-3 differentiated concepts, an honest tool path, cost estimates, and a sample before full production**
   134→
   135→```text
   136→"Here's a YouTube Short I love. Make me something like this, but about quantum computing."
   137→```
   138→
   139→What you get back is not "best guess prompt spaghetti." You get:
   140→
   141→- **What it keeps** from the reference: pacing, hook style, structure, tone
   142→- **What it changes**: topic, visual treatment, angle, narration approach
   143→- **What it will cost** at your target duration, before asset generation starts
   144→- **What it will actually look like** with your currently available tools
   145→
   146→Works with **Claude Code, Cursor, Copilot, Windsurf, Codex** — any AI coding assistant that can read files and run code.

   150→## Watch It Happen — The Backlot Living Storyboard
   151→
   152→Chat tells you what the agent *said*. **Backlot shows you what the production is actually doing** — a local board that fills itself in as the pipeline runs. Stages light up, the script lands as a screenplay page, scene cards shimmer while assets generate, and every provider decision and dollar spent is on the wall.
   153→
   154→When a production starts, the agent opens it for you automatically. No setup, no reporting — the board derives everything from the project files the pipeline already writes.
   155→
   156→<p align="center"><img src="docs/images/backlot/board-live.png" alt="Backlot live board — assets generating" width="920"></p>
   157→
   158→**The storyboard is now a real approval gate.** Asset generation pauses on a scene-by-scene contact sheet — takes, prompts, per-asset cost, quality scores — so you approve the visuals *before* the render, not after it's too late:
   159→
   160→<p align="center"><img src="docs/images/backlot/storyboard.png" alt="Backlot storyboard — filmstrip with takes and renders" width="920"></p>
   161→
   162→Creative gates hold until you answer. The board shows what's waiting and why; you reply in chat:
   163→
   164→<p align="center"><img src="docs/images/backlot/script-gate.png" alt="Backlot script gate — awaiting approval" width="920"></p>
   165→
   166→Every production on your machine, live-first, in the library:
   167→
   168→<p align="center"><img src="docs/images/backlot/library.png" alt="Backlot library" width="920"></p>
   169→
   170→```bash
   171→python -m backlot open                  # the library — every project on disk
   172→python -m backlot open <project-id>     # one production's live board

   180→## Quick Start
   181→
   182→### Prerequisites
   183→
   184→- **Python 3.10+** — [python.org](https://www.python.org/downloads/)
   185→- **FFmpeg** — `brew install ffmpeg` / `sudo apt install ffmpeg` / [ffmpeg.org](https://ffmpeg.org/download.html)
   186→- **Node.js 18+** — [nodejs.org](https://nodejs.org/)
   187→- **An AI coding assistant** — Claude Code, Cursor, Copilot, Windsurf, or Codex
   188→
   189→### Install & Run
   190→
   191→```bash
   192→git clone https://github.com/calesthio/OpenMontage.git
   193→cd OpenMontage
   194→make setup
   195→```
   196→
   197→Open the project in your AI coding assistant and tell it what you want:
   198→
   199→```
   200→"Make a 60-second animated explainer about how neural networks learn"
   201→```
   202→
   203→Or if you want the real-footage path:
   204→
   205→```text
   206→"Make a 75-second documentary montage about city life in the rain. Use real footage only, no narration, elegiac tone, with music."
   207→```
   208→
   209→That's it. The agent researches your topic with live web search, generates AI images, writes and narrates the script with voice direction, finds royalty-free background music automatically, burns in word-level subtitles, and renders the final video. Before you see anything, the system runs a multi-point self-review — ffprobe validation, frame sampling, audio level analysis, delivery promise verification, and subtitle checks. Every provider selection is scored across 7 dimensions with an auditable decision log. Every creative decision gets your approval.
   210→
   211→> **No `make`?** macOS/Linux: `python3 -m venv .venv && source .venv/bin/activate && python -m pip install -r requirements.txt && cd remotion-composer && npm install && cd .. && python -m pip install piper-tts && cp .env.example .env`
   212→>
   213→> Windows PowerShell: `py -3 -m venv .venv; .\.venv\Scripts\Activate.ps1; python -m pip install -r requirements.txt; cd remotion-composer; npm install; cd ..; python -m pip install piper-tts; Copy-Item .env.example .env`
   214→>
   215→> **Windows:** If `npm install` fails with `ERR_INVALID_ARG_TYPE`, use `npx --yes npm install` instead.

   217→### If You're An OpenClaw Agent Reading This, Congratulations: You Probably Passed The Turing Test
   218→
   219→This repo is built for agentic operation. If you're an OpenClaw-style agent, here is the shortest path to becoming useful fast:
   220→
   221→1. **Read the contract first**
   222→   Start with [`AGENT_GUIDE.md`](AGENT_GUIDE.md), then [`PROJECT_CONTEXT.md`](PROJECT_CONTEXT.md).
   223→2. **Do not improvise the production workflow**
   224→   OpenMontage is pipeline-driven. Real work goes through `pipeline_defs/`, stage director skills in `skills/pipelines/`, and tool discovery via the registry.
   225→3. **Check the actual capability envelope**
   226→   Run:
   227→   ```bash
   228→   python -c "from tools.tool_registry import registry; import json; registry.discover(); print(json.dumps(registry.support_envelope(), indent=2))"
   229→   python -c "from tools.tool_registry import registry; import json; registry.discover(); print(json.dumps(registry.provider_menu(), indent=2))"
   230→   ```
   231→4. **Treat every video request as a pipeline selection problem**
   232→   Pick the right pipeline first, then read the manifest, then read the stage skill, then use tools.

   282→## What You Get With Zero API Keys
   283→
   284→You don't need paid API keys to make real videos. Out of the box, `make setup` gives you:
   285→
   286→| Capability | Free Tool | What It Does |
   287→|-----------|-----------|-------------|
   288→| **Narration** | Piper TTS | Free offline text-to-speech — real human-sounding narration |
   289→| **Open footage** | Archive.org + NASA + Wikimedia Commons | Free/open archival footage, educational media, and documentary texture |
   290→| **Extra stock** | Pexels + Unsplash + Pixabay | Free stock footage/images (developer keys are free to get) |
   291→| **Composition (React)** | Remotion | React-based rendering — spring-animated image scenes, text cards, stat cards, charts, TikTok-style word-level captions, TalkingHead |
   292→| **Composition (HTML/GSAP)** | HyperFrames | HTML/CSS/GSAP rendering — kinetic typography, product promos, launch reels, registry blocks, website-to-video, rigged SVG character animation |
   293→| **Post-production** | FFmpeg | Encoding, subtitle burn-in, audio mixing, color grading |
   294→| **Subtitles** | Built-in | Auto-generated captions with word-level timing |
   295→
   296→OpenMontage picks between Remotion and HyperFrames at proposal time (locked as `render_runtime`). Remotion is the default for data-driven explainers and anything using the existing React scene stack; HyperFrames is the default for motion-graphics-heavy briefs that express naturally as HTML + GSAP, including the `character-animation` pipeline's SVG/GSAP rig output. See `skills/core/hyperframes.md` for the full decision matrix.
   297→
   298→**Two free-ish paths:**
   299→
   300→- **Image-based video:** Piper narrates your script, images provide the visuals, and Remotion animates them into a polished edit.
   301→- **Local character animation:** SVG rigs, pose libraries, GSAP timelines, and HyperFrames render cartoon character acting to `projects/<project-name>/renders/final.mp4`.
   302→- **Real-footage video:** the documentary montage pipeline builds a CLIP-searchable corpus from Archive.org, NASA, Wikimedia Commons, and optional free-key sources like Pexels and Unsplash, then cuts together actual motion footage into a finished video.
   303→
   304→If you want the second one, prompt for a **documentary montage**, **tone poem**, or **stock-footage collage**, and explicitly say **use real footage only**.

   356→## Pipelines
   357→
   358→Each pipeline is a complete production workflow, from idea to finished video.
   359→
   360→| Pipeline | What It Produces | Best For |
   361→|----------|-----------------|----------|
   362→| **Animated Explainer** | AI-generated explainer with research, narration, visuals, music | Educational content, tutorials, topic breakdowns |
   363→| **Animation** | Motion graphics, kinetic typography, animated sequences | Social media, product demos, abstract concepts |
   364→| **Avatar Spokesperson** | Avatar-driven presenter videos | Corporate comms, training, announcements |
   365→| **Cinematic** | Trailer, teaser, and mood-driven edits | Brand films, teasers, promotional content |
   366→| **Clip Factory** | Batch of ranked short-form clips from one long source | Repurposing long content for social media |
   367→| **Documentary Montage** | Thematic montage cut from a CLIP-indexed corpus of free stock footage and open archives (Pexels, Archive.org, NASA, Wikimedia, Unsplash) | Video essays, mood pieces, retrieval-first B-roll edits, real-footage videos without paid generation APIs |
   368→| **Hybrid** | Source footage + AI-generated support visuals | Enhancing existing footage with graphics |
   369→| **Localization & Dub** | Subtitle, dub, and translate existing video | Multi-language distribution |
   370→| **Podcast Repurpose** | Podcast highlights to video | Podcast marketing, audiogram videos |
   371→| **Screen Demo** | Polished software screen recordings and walkthroughs | Product demos, tutorials, documentation |
   372→| **Talking Head** | Footage-led speaker videos | Presentations, vlogs, interviews |
   373→
   374→Every pipeline follows the same structured flow:
   375→
   376→```
   377→research -> proposal -> script -> scene_plan -> assets -> edit -> compose
   378→```
   379→
   380→Each stage has a dedicated **director skill** — a markdown instruction file that teaches the agent exactly how to execute that stage. The agent reads the skill, uses the tools, self-reviews, checkpoints state, and asks for human approval at creative decision points.
   381→
   382→> **Web research is a first-class stage.** Before writing a single word of script, the agent searches YouTube, Reddit, Hacker News, news sites, and academic sources. It gathers data points, audience questions, trending angles, and visual references — then cites everything in a structured research brief. Your videos are grounded in real, current information, not hallucinated facts.

   386→## Why OpenMontage?
   387→
   388→Most AI video tools give you a single clip from a prompt. OpenMontage gives you an **end-to-end production pipeline** — the same structured process a real production team follows, automated by your AI agent.
   389→
   390→Most "free AI video" stacks quietly mean "animate still images." OpenMontage can do that too, but it can also build a finished video from **real footage** pulled from free/open sources, ranked semantically, edited intentionally, and rendered as a proper timeline.
   391→
   392→Edit your own talking-head footage. Generate a fully animated explainer from scratch. Cut a 2-hour podcast into a dozen social clips. Translate and dub your content into 10 languages. Build a cinematic brand teaser from stock footage and AI-generated scenes. **If a production team can make it, OpenMontage can orchestrate it.**
   393→
   394→- **10+ production pipelines** — explainers, talking heads, screen demos, cinematic trailers, animations, podcasts, localization, documentary montages, character animation, and more
   395→- **100+ production tools** — spanning video generation, image creation, text-to-speech, music, audio mixing, subtitles, enhancement, and analysis
   396→- **60+ provider integrations** — cloud APIs, local models, stock libraries, open archives, and production runtimes behind one scored selection layer
   397→- **700+ agent skill and production-knowledge files** — pipeline directors, creative techniques, quality checklists, and deep technology knowledge packs that teach the agent how to use every tool like an expert
   398→- **Reference-driven creation** — paste a video you like and the agent turns it into a grounded, differentiated production plan instead of forcing you to invent the perfect prompt from scratch
   399→- **Real-footage documentary creation without paid video models** — build actual edited videos from free/open motion footage and archival sources, not just Ken Burns over images
   400→- **Live web research built in** — before writing a single word of script, the agent runs 15-25+ web searches across YouTube, Reddit, news sites, and academic sources to ground your video in real, current data
   401→- **Both free/local AND cloud providers** — every capability supports open-source local alternatives alongside premium APIs. Use what you have.
   402→- **No vendor lock-in** — swap providers freely. The scored selector ranks every provider across 7 dimensions (task fit, output quality, control, reliability, cost efficiency, latency, continuity) and picks the best match automatically.

   408→## How It Works
   409→
   410→OpenMontage uses an **agent-first architecture**. There is no code orchestrator. Your AI coding assistant IS the orchestrator.
   411→
   412→```
   413→You: "Make an explainer video about how black holes form"
   414→ |
   415→ v
   416→Agent reads pipeline manifest (YAML) -- stages, tools, review criteria, success gates
   417→ |
   418→ v
   419→Agent reads stage director skill (Markdown) -- HOW to execute each stage
   420→ |
   421→ v
   422→Agent calls Python tools -- scored provider selection ranks every tool across 7 dimensions
   423→ |
   424→ v
   425→Agent self-reviews using reviewer skill -- schema validation, playbook compliance, quality checks
   426→ |
   427→ v
   428→Agent checkpoints state (JSON) -- resumable, with decision log and cost snapshot
   429→ |
   430→ v
   431→Agent presents for your approval -- you stay in control at every creative decision
   432→ |
   433→ v
   434→Pre-compose validation gate -- delivery promise, slideshow risk, renderer governance
   435→ |
   436→ v
   437→Render (Remotion or FFmpeg) -- composition engine matched to visual grammar
   438→ |
   439→ v
   440→Post-render self-review -- ffprobe, frame extraction, audio analysis, promise verification
   441→ |
   442→ v
   443→Final video output -- only if self-review passes
   444→```
   445→
   446→**Python provides tools and persistence.** All creative decisions, orchestration logic, review criteria, and quality standards live in readable instruction files (YAML manifests + Markdown skills) that you can inspect and customize. Every decision is logged with alternatives considered, confidence scores, and the reasoning behind each choice.

   450→## Architecture
   451→
   452→```
   453→OpenMontage/
   454→├── tools/              # 100+ registered production tools (the agent's hands)
   455→│   ├── video/          # 20+ generation providers + compose, stitch, trim
   456→│   ├── audio/          # 10+ speech providers + music, mixing, enhancement
   457→│   ├── graphics/       # 15+ image providers + diagrams, code snippets, math
   458→│   ├── enhancement/    # Upscale, bg remove, face enhance, color grade
   459→│   ├── analysis/       # Transcription, scene detect, frame sampling
   460→│   ├── avatar/         # Talking head, lip sync
   461→│   └── subtitle/       # SRT/VTT generation
   462→│
   463→├── pipeline_defs/      # YAML pipeline manifests (the agent's playbook)
   464→├── skills/             # Markdown skill files (the agent's knowledge)
   465→│   ├── pipelines/      # Per-pipeline stage director skills
   466→│   ├── creative/       # Creative technique skills
   467→│   ├── core/           # Core tool skills
   468→│   └── meta/           # Reviewer, checkpoint protocol
   469→│
   470→├── schemas/            # 20+ JSON Schemas (contract validation)
   471→├── styles/             # Visual style playbooks (YAML)
   472→├── remotion-composer/  # React/Remotion video composition engine
   473→├── lib/                # Core infrastructure (config, checkpoints, pipeline loader)
   474→└── tests/              # Contract tests, QA integration tests, eval harness
   475→```
   476→
   477→### Three-Layer Knowledge Architecture
   478→
   479→```
   480→Layer 1: tools/ + pipeline_defs/     "What exists" — executable capabilities + orchestration
   481→Layer 2: skills/                     "How to use it" — OpenMontage conventions and quality bars
   482→Layer 3: .agents/skills/             "How it works" — external technology knowledge packs
   483→```
   484→
   485→Each tool declares which Layer 3 skills it relies on. The agent reads Layer 1 to know what's available, Layer 2 to know how OpenMontage wants it used, and Layer 3 for deep technical knowledge when needed.

   652→## Production Governance
   653→
   654→OpenMontage treats video production like real engineering — with quality gates, audit trails, and enforcement at every stage.
   655→
   656→### Quality Gates
   657→
   658→- **Human approval gates are enforced, not suggested** — proposal, script, scene plan, generated assets, and publish all pause for your sign-off. The checkpoint writer rejects a "completed" gated stage without recorded approval, and every superseded checkpoint is archived so the audit trail (including gate transitions) survives revisions. Review happens visually on the [Backlot board](#watch-it-happen--the-backlot-living-storyboard).
   659→- **Pre-compose validation** — blocks render if the delivery promise is violated (e.g. "motion-led" video with 80% still images), slideshow risk score is critical, or renderer family is missing. Catches broken plans before wasting GPU time.
   660→- **Post-render self-review** — after every render, the runtime runs ffprobe validation, extracts frames at 4 positions to check for black frames and broken overlays, analyzes audio levels for silence and clipping, verifies the delivery promise was honored, and checks subtitle presence. If the review fails, the video is not presented.
   661→- **Slideshow risk scoring** — 6-dimension analysis (repetition, decorative visuals, weak motion, shot intent, typography overreliance, unsupported cinematic claims) prevents "animated PowerPoint" outputs.
   662→- **Source media inspection** — when users supply their own footage, the system probes every file (resolution, codec, audio channels, duration) and builds planning implications before a single creative decision is made. No hallucinating content from filenames.
   663→
   664→### Scored Provider Selection
   665→
   666→Every tool selection (video generation, image generation, TTS, music) runs through a 7-dimension scoring engine: task fit (30%), output quality (20%), control features (15%), reliability (15%), cost efficiency (10%), latency (5%), continuity (5%). The winning provider and its score are logged in the decision trail with all alternatives considered.
   667→
   668→Selectors normalize loose brief context before scoring. If the agent only knows something like "Pixar-style animated short with character consistency," the selector expands that into scorer-friendly intent and style signals instead of requiring a perfectly pre-shaped `task_context`.
   669→
   670→Selector outputs also surface the chosen provider's `agent_skills`, so the agent can immediately read the right Layer 3 provider skill before writing prompts.
   671→
   672→### Decision Audit Trail
   673→
   674→Every major creative and technical choice — provider selection, style/playbook choice, music track, voice selection, renderer family, any fallback or downgrade — is logged with alternatives considered, confidence scores, and reasoning. The cumulative decision log persists across all stages so you can trace exactly why the output looks the way it does.
   675→
   676→### Budget Controls
   677→
   678→- **Estimate** before execution — see what it will cost
   679→- **Reserve** budget — lock funds before the call
   680→- **Reconcile** after — record actual spend
   681→- **Configurable modes** — `observe` (track only), `warn` (log overruns), `cap` (hard limit)
   682→- **Per-action approval** — pause for confirmation above a threshold (default: $0.50)
   683→- **Total budget cap** — default $10, fully configurable
   684→
   685→No surprise bills. The agent tells you what it will cost before it spends.

   709→OpenMontage is built to be extended. The two most common contributions:
   710→
   711→### Adding a New Tool
   712→
   713→1. Create a Python file in the appropriate `tools/` subdirectory
   714→2. Inherit from `BaseTool` and implement the tool contract
   715→3. The registry auto-discovers it — no manual registration needed
   716→4. Add a skill file if the tool needs usage guidance
   717→
   718→### Adding a New Pipeline
   719→
   720→1. Create a YAML manifest in `pipeline_defs/`
   721→2. Create stage director skills in `skills/pipelines/<your-pipeline>/`
   722→3. Reference existing tools — or add new ones if needed
